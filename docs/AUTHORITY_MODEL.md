# Authority Model

Infrastructure authentication proves a service/user identity; it does not prove clinical or business authority. Authority is a Sovereign decision using tenant, patient, role, grant, purpose, action class, content version, evidence, state, conditions, time, and policy version.

## Intent and execution

Only decided/ordered/authorized intent with required actor authority may create executable consequences. Discussion, considered, conditional-but-unsatisfied, recommended, deferred, rejected, superseded, ambiguous, or unknown intent cannot.

Class A/B/C/D define risk; policy grants execution. Class D remains human. Class C approval binds the exact transaction hash and expires/revokes according to policy. Revalidation occurs immediately before adapter invocation.

All denials are reason-coded. Break-glass, if later approved, requires explicit scope, reason, time limit, notification, heightened audit, and retrospective review; it may not allow an AI principal to assume clinician authority.
